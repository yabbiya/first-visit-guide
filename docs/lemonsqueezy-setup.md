## 1. 왜 결제를 붙이나, 왜 Lemon Squeezy인가

- **배경**: 사이트의 핵심(휴무·예약·입장 조건·안전 정보)은 언제나 무료로 두고, 부가 기능 2개
  ("오늘은 꼭 가야 해요" 모드 `mustgo`, 덜 붐비는 날 추천 `quiet-days`)만 평생 이용권으로 잠글 계획이다.
- **Lemon Squeezy를 고른 이유**: 판매 대행(Merchant of Record)이라 해외 손님의 부가세를 대신 처리해 주고,
  한국으로 정산된다. 개인이 나라별 세금을 직접 신고하지 않아도 된다.
- **라이선스 키 방식**: 회원가입·로그인 서버를 따로 만들지 않고, 결제하면 발급되는 키를 사이트가 LS에 물어보는
  방식으로 단순하게 유지했다(`api/license.js`).

## 2. 진행 순서와 그때 내린 판단

### 2-1. 사이트 전용 Gmail 만들기
- **대안**: 평소 쓰는 개인 메일 vs 새 메일.
- **결정**: 새 메일(`firstvisitkoreanotes@gmail.com`)을 만들었다.
- **이유**: 이 주소는 약관·환불 페이지와 영수증에 **공개 문의처로 노출**된다. 개인 메일을 공개하지 않고,
  사이트 관련 메일만 한곳에 모으기 위해서다. 받은 메일은 개인 메일로 자동 전달되게 해서 놓치지 않게 했다.
- 2단계 인증을 켰고, **복구 코드는 프로젝트 폴더가 아닌 다른 곳에 저장**했다.
  이 저장소는 공개(GitHub)라서 폴더 안에 두면 누구나 볼 수 있기 때문이다.

### 2-2. LS 가입·가게 만들기
- 가게 이름: **First Visit Korea Notes** / 가게 주소: `firstvisitkoreanotes.lemonsqueezy.com`
- **막힌 점**: 가입 화면의 "이름" 칸에 가게 이름을 넣었다가, 본인 이름(여권 영문 표기)을 넣는 칸이라는 걸 확인하고 고쳤다.
  본인 확인 단계에서 여권과 이름이 맞아야 하기 때문이다.
- LS 계정에도 2단계 인증을 켰다.

### 2-3. 가격 $3 → $5로 변경
- **계기**: 가게 활성화 신청서에 "무엇을 얼마에 파는지" 적는 칸이 나왔다. 심사자가 신청서와 사이트 가격을 맞춰 볼 수 있어,
  신청 전에 가격을 확정해야 했다.
- **판단 근거 — 고정 수수료**: LS 수수료는 판매 1건마다 5% + 고정 50센트다(가입 시점 안내 기준).
  $3이면 수수료 비중이 약 22%, $5면 약 15%로 줄어든다. 손님 입장에서 $3과 $5의 차이는 작다고 봤다.
- **바꾼 곳**: `ui-text.js`(4개 언어), `index.html`, `terms.html` 등 (커밋 5aeb5aa).

### 2-4. 약관·환불·개인정보 빈칸 채우기
- **계기**: 심사 안내에 "임시 페이지나 공사 중인 사이트는 지원하지 않는다"는 문구가 있었다.
  빈칸(`[CONTACT EMAIL]` 같은 대괄호)이 남은 약관은 공사 중으로 보일 수 있다.
- **정한 것**: 공개 문의 이메일 = 사이트 전용 Gmail, **환불 기간 14일**.
- 원래 `npm run build`는 결제 링크가 들어갔는데 약관에 빈칸이 남아 있으면 배포를 막도록 만들어 두었다.
  이번엔 결제 링크보다 먼저 빈칸을 채웠다.
- **실수와 바로잡기**: 심사 신청을 낸 시점에 이 커밋이 아직 인터넷에 올라가지 않은 상태였다.
  바로 올리고(push), 실제 사이트에서 US$5·이메일·14일이 보이는지 확인했다.

### 2-5. 본인 확인 (Stripe를 통한 신원 확인)
- 여권 촬영까지 마치고 제출 → 현재 **In Review(심사 중)**.
- 계좌·여권 정보는 사용자 본인이 LS 화면에서 직접 넣었다. (개인정보라 대화나 저장소에는 남기지 않는다.)

### 2-6. 테스트 모드로 상품 만들기
| 항목 | 값 | 이유 |
|---|---|---|
| 이름 | Lifetime Pass | 결제 화면에서 바로 이해되는 짧은 이름 |
| 결제 방식 | Single payment | 구독이 아닌 한 번 결제 |
| 가격 | $5 USD | 2-3 참고 |
| 세금 분류 | SaaS – personal use | 개인이 쓰는 온라인 서비스 |
| 라이선스 키 | 켬 | 사이트가 이 키로 기능을 연다 |
| 사용 기간 | Unlimited | "평생" 이용권과 맞춤 (기본값 1 Year를 바꿈) |
| 기기 수 | 3 | 기본값 5에서 줄임. 무제한으로 두면 키를 여러 사람이 나눠 쓸 수 있어서 |
| 파일 | 없음 | 파일을 파는 게 아니라 기능을 여는 열쇠라서 |

- **막힌 점 — 가격이 원화(₩)로 나옴**: 가게 통화가 기본으로 원화였다. Settings → General에서 USD로 바꿨는데
  저장 버튼에 반응이 없어 보여 헷갈렸다. 설정 칸은 이미 USD였고, 이후 상품 화면 가격도 $로 나왔다.
- **테스트 모드로 먼저 한 이유**: 심사가 끝나기 전에도 시험 결제로 라이선스 키 발급 → 사이트에서 기능 열림까지
  확인해 볼 수 있다. 진짜 돈은 오가지 않는다.

## 3. 남은 일

1. **Vercel 환경변수 넣기** (사용자가 직접, 번호는 대화에 보내지 않음)
   - `LEMONSQUEEZY_STORE_ID` = 가게 번호
   - `LEMONSQUEEZY_PRODUCT_ID` = 상품 번호
   - 넣은 뒤 Redeploy
2. **시험 결제로 확인**: 테스트 모드 결제 → 키 발급 → 사이트에 키 입력 → 잠긴 기능이 열리는지.
3. **심사 통과 후**: 상품을 실제 판매 모드(live)로 옮긴다. 이때 상품 번호가 바뀌면 `LEMONSQUEEZY_PRODUCT_ID`만 새로 바꾼다.
4. **결제 링크 연결**: `premium.json`에 `checkoutUrl`(결제 링크)과 잠글 기능 `["mustgo", "quiet-days"]`를 넣고
   `npm run build` → 커밋 → 올리기.
5. (참고) 한국 세금·사업자등록 필요 여부는 홈택스 또는 국세청 상담센터(126)에 확인.

## 4. 지킨 원칙

- API 키·비밀번호·계좌·여권 정보는 코드와 대화에 남기지 않는다. 가게·상품 번호도 Vercel 환경변수에만 둔다.
- 입장에 꼭 필요한 정보(휴무·예약·입장 조건·안전)는 결제와 상관없이 항상 무료.
- 개인 메일 주소는 외부에 공개하지 않고, 공개용은 사이트 전용 메일만 쓴다.
