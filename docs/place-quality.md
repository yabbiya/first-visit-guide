# 장소 품질 기준

> 새 장소는 [place-template.json](place-template.json)을 복사해서 시작한다.

장소를 추가하거나 고칠 때 이 기준을 통과해야 올린다.
목표는 "장소 수"가 아니라 **"믿고 따라가도 되는 메모"**다.

> 이 기준은 실제로 겪은 일에서 나왔다.
> - 일산 MBC: 신분증 안내가 약해져서 "도착하고도 못 들어갈 뻔했다" → 출입 조건을 1번 항목으로
> - 서울숲: 화장실 위치를 못 찾았는데 지어내지 않았다 → "확인 못함"도 기록하기
> - 요약과 카드의 중복 → "한 사실은 한 카드에"

---

## 1. 조사 체크리스트

모든 장소는 아래 항목을 **하나도 빠짐없이 살펴보고**, 항목마다 결과를 셋 중 하나로 남긴다.

- **메모 있음**: 메모로 썼다
- **해당 없음**: 이 장소에는 필요 없다 (예: 공원의 출입 절차)
- **확인 못함**: 찾아봤지만 믿을 만한 자료가 없다 → 지어내지 않는다

### 꼭 살펴볼 항목 (모든 장소)
| # | 항목 | 살펴볼 것 | 비고 |
|---|---|---|---|
| 1 | **출입 조건** | 여는 시간, 요금, 예약, 신분증·방문 등록, 나이 제한 | 없으면 목적을 못 이루는 정보는 `pin` |
| 2 | **대중교통** | 가장 가까운 역·출구 번호, 걸어서 몇 분, 버스 정류장 이름 | `onlyMode: transit` |
| 3 | **자차** | 들어가는 길, 주차 가능 여부·요금·혼잡, 안 될 때 대안 | `onlyMode: car` |
| 4 | **헷갈리는 것** | 이름 비슷한 장소·역, 입구 여러 개, 지도 앱 검색 함정 | 길치 조건, 빨간 주의 카드 |
| 5 | **도착한 뒤** | 안내데스크·안내도 위치, 길 잃었을 때 기준점 | 길치 조건 |

### 상황별 항목
| # | 항목 | 살펴볼 것 |
|---|---|---|
| 6 | **아이 동반** | 화장실, 수유실·기저귀 교환대, 유모차(대여·이동), 놀거리 |
| 7 | **챙길 것** | 안에서 살 수 없는 것(물·간식), 날씨 대비, 준비물 |
| 8 | **붐비는 때** | 특히 몰리는 날·시간(어린이날, 주말 오후, 축제·행사 기간), 그때의 대안(이른 시간, 다른 입구·주차장) |

> 8번은 관광지라면 한국관광공사 "관광지 집중률 예측"(앞으로 30일, 상대 점수) 데이터로 화면에 자동 표시할 수 있다.
> 목록에 없는 장소(업무 장소 등)는 조사한 메모로 대신한다.

## 2. 신뢰도 표시 기준

| 자료 상태 | 표시 (`trust`) |
|---|---|
| 기관 공식 안내, 또는 **직접 방문**으로 확인 | 표시 없음 |
| 후기 한 곳뿐이거나, 2년 넘은 자료 | `확인 필요` |
| 자료끼리 서로 다름 | `후기 엇갈림` 또는 `요금 확인 필요`처럼 무엇이 다른지 |
| 못 찾음 | 메모로 쓰지 않음 → 체크리스트에 "확인 못함" |

- 메모마다 `source`(출처)를 쓴다. 직접 가본 내용은 `직접 방문(날짜)`.
- 네이버 지도 리뷰·인스타그램은 크롤링하지 않는다(약관 위반).
- 사진은 직접 찍었거나 사용 허락받은 것만, `credit` 필수.
- **대표 사진(`cover`)**: 직접 찍은 사진, 공공누리, 위키미디아 공용의 자유 이용 사진(CC0, CC BY, CC BY-SA)만 쓴다.
  `credit`(촬영자), `license`, `link`(원본 페이지) 필수. **지금 모습과 다른 옛 사진은 쓰지 않는다**
  (예: 광화문광장은 2022년 8월 재개장 이후 사진만). 가로 사진을 고르고, 가로 1280px로 줄여서 넣는다.
  알맞은 사진이 없으면 넣지 않는다(색 배경이 나온다).
- **대표 사진은 "그 장소만의 모습"이어야 한다.** "이 사진만 보고 이 장소인 줄 알 수 있나?"를 먼저 묻는다.
  - 탈락: 안내판·글자 조형물(장소 이름을 보여줄 뿐 모습이 아님), 어느 동네 공원에나 있는 데크·벤치,
    꽃·동물 클로즈업(한철 풍경이거나 장소를 상징하지 않음), 주변 건물이 주인공인 먼 풍경
  - 좋음: 그 장소의 대표 풍경이 넓게 보이는 사진 (예: 서울숲 = 넓은 잔디밭 + 이어진 숲 + 숲 너머 고층 건물)
  - 직접 찍은 사진이 가장 좋다. 다만 **사람이 알아볼 수 있게 나오면 쓰지 않거나 지운 뒤에** 쓴다(공개 사이트).

## 3. 쓰는 규칙

1. **제목만 읽어도 핵심이 전달되게** 쓴다. "꼭 기억할 3가지"에는 제목만 보인다.
   - 좋음: "정발산역 1번 출구로 나오세요" / 아쉬움: "가는 길 안내"
2. **한 사실은 한 카드에만.** 다른 카드에 이미 있으면 반복하지 않는다.
3. **출입 필수 정보는 제목에 + `pin: true`** (장소당 2개까지).
   메모를 합치거나 줄일 때 이런 정보가 제목에서 빠지지 않았는지 다시 본다.
4. **숫자는 구체적으로**: "가까워요" 대신 "걸어서 5분", "출구 1번", "5분당 150원".
   단, **확인 안 된 숫자(`확인 필요`가 붙은 요금 등)는 제목에 넣지 않는다.** 접힌 카드는 제목만 보여서
   불확실한 숫자가 확실한 정보처럼 보인다. 본문에 쓰고 표시를 붙인다.
5. 말투는 "~요"체, 한 카드 본문은 3문장 이내.

## 4. 올리기 전 확인

- [ ] 체크리스트 1~8번 모두 결과가 남아 있다
- [ ] 출입 조건(1번)이 "메모 있음"이면 제목에 들어가 있고 `pin`이 붙어 있다
- [ ] 모든 메모에 출처가 있다
- [ ] 같은 사실이 두 카드에 나오지 않는다
- [ ] `npm run build` 검사 통과
- [ ] 휴대폰 크기 화면에서 스위치 조합(기본 / 길치 / 아이 / 자차)을 눌러 "꼭 기억할 3가지"가 자연스럽다

## 5. 장소 파일의 `checked` 항목

체크리스트 결과를 장소 파일에 남긴다. 빠진 항목은 `npm run build`가 알려준다.

```json
"checked": {
  "entry": "id-card",
  "transit": "exit",
  "car": "parking",
  "confusing": "not-sangam",
  "arrival": "landmark",
  "kid": "lake-park",
  "bring": "확인 못함",
  "crowd": "확인 못함"
}
```

- 값에 쓸 수 있는 것
  - 메모 `id` (= 메모 있음). 여러 메모가 다루면 목록으로: `["exit", "bus"]`
  - `"해당 없음"`: 이 장소에는 필요 없음
  - `"확인 못함"`: 찾아봤지만 믿을 만한 자료가 없음
  - `"기본 정보에 표시"`: 장소 이름 아래 여는 시간·요금(`hours`, `fee`)으로 충분함 (예: 24시간 무료 공원)
- 항목이 빠져 있거나, 없는 메모 id를 가리키거나, 모르는 항목이 있으면 `npm run build`에서 알려준다.
