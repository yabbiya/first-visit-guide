# 장소 품질 기준

> 새 장소는 [place-template.json](place-template.json)을 복사해서 시작한다.

장소를 추가하거나 고칠 때 이 기준을 통과해야 올린다.
목표는 "장소 수"가 아니라 **"믿고 따라가도 되는 메모"**다.

> 이 기준은 실제로 겪은 일에서 나왔다.
> - 일산 MBC: 신분증 안내가 약해져서 "도착하고도 못 들어갈 뻔했다" → 출입 조건을 1번 항목으로
> - 서울숲: 화장실 위치를 못 찾았는데 지어내지 않았다 → "확인 못함"도 기록하기
> - 요약과 카드의 중복 → "한 사실은 한 카드에"

---

## 1. 조사 체크리스트

모든 장소는 아래 항목을 **하나도 빠짐없이 살펴보고**, 항목마다 결과를 셋 중 하나로 남긴다.

- **메모 있음**: 메모로 썼다
- **해당 없음**: 이 장소에는 필요 없다 (예: 공원의 출입 절차)
- **확인 못함**: 찾아봤지만 믿을 만한 자료가 없다 → 지어내지 않는다

- 체크리스트 결과(`checked.foreign`)에는 위 항목을 다룬 메모 id를 모두 적는다. 하나도 확인하지 못했으면 `"확인 못함"`.
- 2026-11 이전에 추가한 장소는 9-1~9-6 기준으로 다시 조사하지 않았다. 지금 적힌 결과는 예전 기준이다.

> 8번은 관광지라면 한국관광공사 "관광지 집중률 예측"(앞으로 30일, 상대 점수)으로 화면에 자동 표시된다.
> 장소 파일에 `"crowd": { "area": "11", "signgu": "11110", "name": "광화문광장" }`처럼 시도 코드(2자리),
> 시군구 코드(5자리), **관광공사 목록에 적힌 이름 그대로**를 넣는다. 목록에 없는 장소(업무 장소 등)는 넣지 않고
> 조사한 메모로 대신한다.
>
> 10번: 이 메모들은 `conditions`에 `"mustgo"`를 넣는다(모드를 켜면 맨 앞으로). 대기 시간·한산한 시간 같은 숫자는
> 공식 자료나 날짜가 있는 보도로 확인한 것만 쓴다. 못 찾으면 "확인 못함" — 추측해서 "아침이 한산해요"라고 쓰지 않는다.
>
> 11번 쓰는 법 (걸어서 갈 수 있는 이웃, `walkTo`)
> - `npm run build`가 좌표로 직선 2km 이내 장소 쌍을 `docs/walk-candidates.md`에 자동으로 적는다. **이 후보는 화면에 나오지 않는다.**
> - 지도 앱(네이버 지도 등)의 **보행 경로**로 걷는 분·오르막·계단·큰길 건너기를 확인한 것만 `place.json`의 `walkTo`에 적는다.
>   직선거리로 분을 계산해 넣지 않는다. 확인 못 한 쌍은 넣지 않는다(= 화면에 안 나옴).
> - **방향이 있다.** 남대문시장 → 남산서울타워(오르막)와 그 반대(내리막)는 다르다. 떠나는 장소의 파일에 적는다.
> - `kind`: `"skipSubway"`(지하철 타지 말고 걸어가세요) 또는 `"hard"`(가까워 보여도 오르막·계단이라 힘들어요).
>   `hard`는 화면에 "아이·어르신과 함께면 시간이 더 걸려요" 한 줄이 자동으로 붙는다.
> - 지도·경로 그림은 넣지 않는다(이 앱은 길안내 앱이 아니다). 화면에는 네이버 지도 링크만 둔다.
>
> ```json
> "walkTo": [
>   { "to": "changdeokgung", "minutes": 8, "kind": "skipSubway", "note": "평지, 큰길 한 번 건넘",
>     "trust": [], "source": "네이버 지도 보행 경로(사용자 확인)", "checkedOn": "2026-11-02" }
> ]
> ```
> - `i18n.json`의 각 언어에 `"walkTo": { "changdeokgung": "번역한 note" }`도 필수(빠지면 build가 막는다).
> - 체크리스트 `checked.walk`에는 `walkTo`에 적은 장소 id 목록, 또는 `"해당 없음"`·`"확인 못함"`.
>
> 9번: 외국인에게 특히 필요한 메모는 `conditions`에 `"foreign"`을 넣는다(외국어 화면에서 앞으로 올라옴).
> 외국인에게만 필요한 메모(예: 외국어 해설)는 `"audience": "foreign"`도 넣는다(한국어 화면에서는 숨김).
> 택시용 한국어 이름·주소, 네이버 지도·카카오맵 링크, 1330 관광통역안내전화는 외국어 화면에 자동으로 나오므로
> 메모로 쓰지 않고 체크리스트에 "기본 정보에 표시"로 남긴다.

## 2. 신뢰도 표시 기준

| 자료 상태 | 표시 (`trust`) |
|---|---|
| 기관 공식 안내, 또는 **직접 방문**으로 확인 | 표시 없음 |
| 후기 한 곳뿐이거나, 2년 넘은 자료 | `확인 필요` |
| 자료끼리 서로 다름 | `후기 엇갈림` 또는 `요금 확인 필요`처럼 무엇이 다른지 |
| 못 찾음 | 메모로 쓰지 않음 → 체크리스트에 "확인 못함" |

- 메모마다 `source`(출처)를 쓴다. 직접 가본 내용은 `직접 방문(날짜)`.
- 네이버 지도 리뷰·인스타그램은 크롤링하지 않는다(약관 위반).
- 육아 정보 사이트 같은 민간 정보 사이트는 **어디를 확인할지 찾는 힌트로만** 쓰고 출처로 적지 않는다. 내용은 공식 누리집에서 다시 확인한다.
  (맘맘 이용약관 제14조②: 사전 승낙 없는 복제·2차적저작물 작성 금지, 제12조 8호: 동의 없는 영리 이용 금지 — 2026-11 확인)
- 같은 장소에 공식 누리집이 둘이면(예: 옛 운영 주체 누리집과 서울시 공원 누리집) **지금 운영하는 곳**을 기준으로 한다.
- 사진은 직접 찍었거나 사용 허락받은 것만, `credit` 필수.
- **대표 사진 찾는 순서**: ① 한국관광공사 관광정보 API(공공데이터포털 "영문 관광정보서비스_GW", `EngService2`의
  `searchKeyword2`로 장소를 찾고 `detailImage2`로 사진 목록 조회) → 저작권 유형이 `Type1`(공공누리 제1유형)인 것만 사용,
  출처는 "한국관광공사" ② 위키미디아 공용 ③ 직접 촬영. 관광공사 사진이 구도·계절별로 훨씬 다양하다.
  `Type3`(공공누리 제3유형)은 **변경 금지**라서 쓰지 않는다. 우리 화면은 사진을 잘라 쓰고 어두운 막을 덮기 때문이다.
  행사 기간에만 있는 모습(크리스마스 마켓, 행사 부스 등)이 담긴 사진도 쓰지 않는다.
- **대표 사진(`cover`)**: 직접 찍은 사진, 공공누리, 위키미디아 공용의 자유 이용 사진(CC0, CC BY, CC BY-SA)만 쓴다.
  `credit`(촬영자), `license`, `link`(원본 페이지) 필수. **지금 모습과 다른 옛 사진은 쓰지 않는다**
  (예: 광화문광장은 2022년 8월 재개장 이후 사진만). 가로 사진을 고르고, 가로 1280px로 줄여서 넣는다.
  알맞은 사진이 없으면 넣지 않는다(색 배경이 나온다).
- **대표 사진은 "그 장소만의 모습"이어야 한다.** "이 사진만 보고 이 장소인 줄 알 수 있나?"를 먼저 묻는다.
  - 탈락: 안내판·글자 조형물(장소 이름을 보여줄 뿐 모습이 아님), 어느 동네 공원에나 있는 데크·벤치,
    꽃·동물 클로즈업(한철 풍경이거나 장소를 상징하지 않음), 주변 건물이 주인공인 먼 풍경
  - 좋음: 그 장소의 대표 풍경이 넓게 보이는 사진 (예: 서울숲 = 넓은 잔디밭 + 이어진 숲 + 숲 너머 고층 건물)
  - 직접 찍은 사진이 가장 좋다. 다만 **사람이 알아볼 수 있게 나오면 쓰지 않거나 지운 뒤에** 쓴다(공개 사이트).

## 3. 쓰는 규칙

1. **제목만 읽어도 핵심이 전달되게** 쓴다. "꼭 기억할 3가지"에는 제목만 보인다.
   - 좋음: "정발산역 1번 출구로 나오세요" / 아쉬움: "가는 길 안내"
2. **한 사실은 한 카드에만.** 다른 카드에 이미 있으면 반복하지 않는다.
3. **출입 필수 정보는 제목에 + `pin: true`** (장소당 2개까지).
   메모를 합치거나 줄일 때 이런 정보가 제목에서 빠지지 않았는지 다시 본다.
4. **숫자는 구체적으로**: "가까워요" 대신 "걸어서 5분", "출구 1번", "5분당 150원".
   단, **확인 안 된 숫자(`확인 필요`가 붙은 요금 등)는 제목에 넣지 않는다.** 접힌 카드는 제목만 보여서
   불확실한 숫자가 확실한 정보처럼 보인다. 본문에 쓰고 표시를 붙인다.
5. 말투는 "~요"체, 한 카드 본문은 3문장 이내.

## 4. 올리기 전 확인

- [ ] 체크리스트 1~9번 모두 결과가 남아 있다
- [ ] 출입 조건(1번)이 "메모 있음"이면 제목에 들어가 있고 `pin`이 붙어 있다
- [ ] **주소와 좌표를 공식 자료(기관 누리집이나 한국관광공사 관광정보 API의 `addr1`, `mapx`·`mapy`)와 맞춰 봤다**
- [ ] 모든 메모에 출처가 있다
- [ ] 같은 사실이 두 카드에 나오지 않는다
- [ ] `npm run build` 검사 통과
- [ ] 휴대폰 크기 화면에서 아이 동반 스위치를 껐다 켜 보며 "꼭 기억할 3가지"가 자연스럽다

## 5. 장소 파일의 `checked` 항목

체크리스트 결과를 장소 파일에 남긴다. 빠진 항목은 `npm run build`가 알려준다.

```json
"checked": {
  "entry": "id-card",
  "transit": "exit",
  "car": "parking",
  "confusing": "not-sangam",
  "arrival": "landmark",
  "kid": "lake-park",
  "bring": "확인 못함",
  "crowd": "확인 못함",
  "foreign": "확인 못함",
  "mustgo": "확인 못함",
  "walk": "확인 못함"
}
```

- 값에 쓸 수 있는 것
  - 메모 `id` (= 메모 있음). 여러 메모가 다루면 목록으로: `["exit", "bus"]`
  - `"해당 없음"`: 이 장소에는 필요 없음
  - `"확인 못함"`: 찾아봤지만 믿을 만한 자료가 없음
  - `"기본 정보에 표시"`: 장소 이름 아래 여는 시간·요금(`hours`, `fee`)으로 충분함 (예: 24시간 무료 공원)
- 항목이 빠져 있거나, 없는 메모 id를 가리키거나, 모르는 항목이 있으면 `npm run build`에서 알려준다.

## 6. 번역 (`i18n.json`)

장소 폴더에 `i18n.json`을 두면 영어(`en`)·중국어 간체(`zh`)·일본어(`ja`)로 보인다. 원문은 언제나 `place.json`(한국어)이다.

```json
{
  "en": {
    "name": "Gyeongbokgung Palace", "region": "Jongno-gu, Seoul", "notice": "카드 안내 한 줄 번역 (notice가 있을 때)",
    "address": "161 Sajik-ro, Jongno-gu, Seoul", "hours": "…", "fee": "…",
    "memos": { "exit": { "title": "…", "body": "…" } }
  },
  "zh": { … }, "ja": { … }
}
```

- **모든 항목이 필수**: `name`·`region`·`address`·`hours`(요금이 있으면 `fee`)와 **모든 메모**를 세 언어로 번역한다.
  하나라도 빠지면 `npm run build`가 막는다. 번역이 빠진 메모는 외국어 화면에 한국어로 섞여 나오기 때문이다.
- 장소·역 이름은 **한국관광공사 외국어 관광정보의 공식 표기**를 따른다.
- 지도 앱 검색어, 역 이름, 출구 표지판처럼 **현장에서 한국어로 보게 되는 말은 괄호에 한국어를 같이** 쓴다.
  예: `Gwanghwamun Station (광화문역)`, `search for 세종로공영주차장`.
- "~라는 안내가 있어요" 같은 조심스러운 표현은 번역에서도 그대로 살린다. 번역하면서 단정하는 말로 바꾸지 않는다.
- 한국어 원문을 고치면 번역도 같이 고친다. 외국인 전용 메모(`audience: "foreign"`)는 세 언어 번역이 없으면 검사에 걸린다.
